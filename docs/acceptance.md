# 轻量 MVP 验收标准

## 功能

- 无 NAS、无 PostgreSQL 服务、无 `.env` 可以启动；
- 两分钟内完成一次日常输入、分析和保存；
- READY、CAUTION、BLOCKED 及原因清晰可见；
- 项目 WIP 上限由服务端事务强制执行，客户端不能通过伪造计数绕过；
- 可以记录实际结果、决策质量、执行质量和环境影响；
- 日常决策可以关联活动/维护项目，并在关系图谱中形成可追踪边；
- 决策只能按显式状态机推进，首次结果必须经过执行中和待复盘，取消后不可补写结果；
- Web 内置点数、风险与结果复盘教程，窄屏不产生页面级横向溢出；
- 周复盘、项目、历史、审计和关系图谱可访问；
- 周复盘使用明确自然周，统计由服务端保存前重新计算；用户可调整报告值，但系统计算值、逐字段差异、原因和最终值必须分别留存并追加审计；
- 页面、CLI 和 TUI 均可发现本机服务；
- 轻量版默认使用操作系统动态端口，所有客户端读取同一运行状态；
- 页面和 CLI 可以安全关闭服务；
- CLI 支持 JSON 输入输出；
- CLI 支持读取决策、推进执行状态和记录结果；
- CLI 可校验完整审计链，并导出拒绝覆盖的可移植 JSON 快照；
- Windows/Linux 共享命令契约。

## 数据

- 空数据目录可完整迁移和种子初始化；
- PGlite 重启后数据仍存在；
- 同一输入和规则版本得到相同输出；
- 数据目录不能被多个应用实例直接打开；
- 备份非空且能够恢复到独立目录；
- 可将轻量数据提升到空 PostgreSQL 并完成记录对账。

## 工程

- 单元、集成和 HTTP 测试通过；
- TypeScript 严格检查通过；
- 生产构建通过；
- 服务默认仅监听 `127.0.0.1`；
- 启动锁在数据库初始化前生效，失败原因写入用户日志且 CLI 可定位；
- POST 页面具有 CSRF 校验，CLI 使用受保护的运行时令牌；
- 浏览器完成实际纵向闭环和视觉检查；
- Gitea Actions 自动覆盖共享核心、Linux GUI 和 PostgreSQL 合同；Windows 原生客户端在 Win11 上执行可复现构建与交互验收，持续 Windows Runner 属于后续工程化范围。
- Windows 安装包、便携包、启动入口和小组件在系统安全功能保持启用时进行验收；任何用户流程不得要求关闭 Defender、SmartScreen、防火墙或第三方安全软件，也不得要求添加排除项。若被拦截，应报告可验证原因并安全失败。

## 暂不验收

- Windows/Linux 差异化 GUI 完整实现；
- Win11 小组件；
- 离线多主同步；
- LLM 自动正式决策；
- 多用户复杂权限；
- 自动执行外部高风险动作；
- macOS。

## 标准云部署基线

- 云部署档案不得修改或依赖现有 NAS 生产栈；
- 应用镜像使用官方 Node.js 运行时并以非 root 用户运行；
- PostgreSQL 不发布主机端口，应用只绑定主机回环地址；
- 数据库迁移由一次性任务执行，应用副本必须设置 `RUN_MIGRATIONS=false`；
- 存活检查不访问数据库；就绪检查必须同时验证数据库连接和完整迁移集合；
- 密码与会话密钥只通过 secret 文件提供，不进入源码、镜像、日志或命令参数；
- 容器根文件系统只读、移除 Linux capabilities 并启用 `no-new-privileges`；
- 单应用副本限制必须明确，直至登录限速与会话状态具备共享协调；
- 正式部署前将应用和 PostgreSQL 镜像改为已测试的 digest 引用，并完成 HTTPS、备份与恢复演练；
- 静态契约、TypeScript、完整测试、构建和 PostgreSQL 合同均通过后，代码基线才可标记 VERIFIED；真实云主机、域名、证书和恢复演练未完成时，生产部署状态仍为 PARTIAL。
