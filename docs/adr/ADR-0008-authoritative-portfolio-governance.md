# ADR-0008：服务端权威的项目组合治理

状态：ACCEPTED

日期：2026-07-30

## 背景

早期界面显示“WIP ≤ 3”，日常分析也接收 `activeWip`，但项目创建和重新激活没有在事务内执行上限；API 客户端还可以伪造 WIP 数值。这使展示规则与事实写入脱节，并在并发请求下存在越过上限的可能。

周复盘使用按周 upsert，但更新既有周次时曾用新生成且未实际落库的 UUID 追加审计事件，导致同一周复盘可能分裂成多个审计聚合。

## 决策

- WIP 上限读取当前规则版本的 `parameters.wip_limit`，不在 Web、CLI 或原生客户端硬编码；
- 核心 WIP 只统计 `active` 与 `maintaining` 项目；
- 项目创建及进入核心 WIP 的状态变更，在事务内锁定当前规则版本记录并重新计数；
- 达到上限时返回稳定的业务冲突，不写入项目、图谱或审计事件；
- 项目状态必须遵循显式状态机，`retired` 为终态；
- 日常分析由服务端重新读取 WIP 事实和规则上限，客户端提交值只作为显示上下文，不作为正式判断依据；
- 周复盘 upsert 必须使用数据库实际返回的聚合 ID 追加审计事件。

## 后果

所有客户端仍可显示组合容量，但不能绕过服务端规则。规则版本参数变化会同步反映到 Web、CLI、Windows GUI 和 Linux GUI。项目组合写入会被串行化到很短的事务临界区，以换取 PGlite 与 PostgreSQL 一致的上限保证。
