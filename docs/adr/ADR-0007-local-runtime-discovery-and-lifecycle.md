# ADR-0007：本机运行时发现与生命周期保护

状态：ACCEPTED

日期：2026-07-30

## 背景

轻量版最初固定监听 `127.0.0.1:4310`。外部用户机器上的既有应用占用了该端口，而后台启动又丢弃标准错误，最终只表现为无原因的 20 秒超时。同时，原有状态文件在数据库初始化和监听完成后才写入，不能阻止两个同时启动的进程并发打开同一 PGlite 数据目录。

## 决策

- 本机 PGlite 且本地访问模式在未设置 `APP_PORT` 时监听端口 `0`，由操作系统原子分配动态回环端口；
- 服务监听成功后把实际 URL 写入 `service.json`，Web 启动器、CLI、TUI、Windows GUI 和 Linux GUI 均从同一状态文件发现服务；
- CLI 与两种原生 GUI 对版本化 API 统一携带状态文件中的运行时令牌；该令牌只用于同机控制客户端，外部 Web 访问仍走密码会话或可信身份头；
- 判断状态文件是否属于当前服务时，必须用运行时令牌访问受保护的实例确认端点，不能只依赖 PID 或公开健康检查；
- 显式 `APP_PORT`、PostgreSQL 全量版以及非本机访问模式继续使用固定端口，冲突时明确失败；
- 服务在数据库初始化前取得按数据目录划分的启动锁，并在正常关闭或启动失败时释放；
- 后台服务输出追加到用户数据目录的 `logs/service.log`，CLI 监视子进程提前退出并报告日志路径；
- 启动等待上限扩展为 60 秒，但提前退出不等待到超时。

## 不采用

- 不从 `4310` 开始顺序扫描端口，避免侵入其他应用的固定端口；
- 不先打开临时 socket 探测再关闭后重开，避免检查与使用之间的竞态；
- 不由便携版修改 Windows 全局端口排除范围；
- 不以端口占用代替数据目录单实例锁。

## 后果

本机服务 URL 每次启动可能变化，任何客户端和自动化不得硬编码轻量版端口。需要稳定入口的全量部署必须显式设置端口并由反向代理提供外部地址。
