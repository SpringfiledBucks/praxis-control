# ADR-0009：项目关联与决策执行生命周期

状态：ACCEPTED

日期：2026-07-30

## 背景

日常决策此前可以分析、保存和直接记录结果，但没有表达它服务于哪个项目，也没有区分“计划”“正在执行”和“等待复盘”。这会让关系图谱缺少项目—行动事实，并允许尚未执行的计划被直接标记为已闭环。

## 决策

- 日常决策可以不关联项目；如关联，只接受 `active` 或 `maintaining` 项目；
- 项目状态校验、决策写入、知识节点、`advances` 关系和审计事件处于同一事务；校验项目时持有共享行锁，避免并发暂停产生语义漂移；
- 图谱边方向为 `decision --advances--> project`；强度由矛盾贡献 55% 与瓶颈贡献 45% 归一化得到，只表示预期关联强度，不表示实际结果；
- 生命周期为 `planned → executing → awaiting_review → reviewed`；执行中或待复盘可取消，待复盘可退回执行中；`reviewed` 和 `cancelled` 为终态；
- `reviewed` 不能通过通用状态接口直接设置，只能在 `awaiting_review` 写入结果产生；已有结果可以修正并追加 `OUTCOME_CORRECTED` 审计事件；
- 取消记录继续显示在历史页，但不作为工作台的最近行动或待复盘项；
- 工作台“待复盘”只统计 `awaiting_review`，不再把计划中或执行中的决策混入该指标；
- Web、CLI 和 Windows GUI 经统一 JSON API 使用这些规则；Linux GUI 可回退到完整 Web，且不直接访问数据库；
- 教程明确贡献点数互相独立、风险硬门槛优先，以及决策质量与执行质量分开评价。

## 后果

项目可以通过稳定图谱边追踪具体决策，工作台的待复盘与近七日闭环指标具有明确状态来源。便携导出新增 `project_id`；导入器继续严格要求迁移版本和校验和完全一致，因此 004 之前的旧快照不会被当前版本静默导入，必须先在对应旧版本恢复后升级并重新导出。客户端即使构造非法跳转，也只会得到业务冲突而不会写入部分事实。
