# Praxis Control 使用教程

应用内入口：导航栏“教程”或 `/guide`。

## 核心原则

- 点数不是总预算，矛盾贡献、瓶颈贡献、证据强度分别独立评分；
- 0–2 表示几乎无关或无证据，3–4 为弱，5–6 为中等，7–8 为强，9–10 只用于决定性关系或稳定重复证据；
- 精力和注意力填写现实状态，不填写期望状态；
- 高风险缺授权、无恢复路径或损失不可承受时直接阻断，不能靠贡献高分抵消；
- 结果复盘分别评价决策过程和执行质量，不根据结果好坏倒推；
- 关联项目后，决策会通过稳定 ID 和 `advances` 关系进入图谱；
- 执行状态依次记录为已计划、执行中、待复盘、已闭环；取消后不再补写结果，应新建决策保留历史边界。

完整评分锚点、示例和两分钟操作流程以应用内教程为准，两处内容在同一版本发布。

## 周复盘统计

- 周复盘按自然周统计，不把滚动七天混入本周口径；
- 页面先显示系统根据正式决策和结果计算的统计；
- 可以修改报告中的决策数、闭环数和质量平均值，但修改时必须说明事实遗漏、记录修正或口径差异；
- 系统原值、人工调整、调整原因和最终报告值都会保留，人工修改不会覆盖正式记录；
- 主要矛盾、瓶颈、证据变化、组合调整和下周目标仍由用户判断和编辑。

## 执行状态

1. 保存后为“已计划”；
2. 真正开始时推进为“执行中”；
3. 达到停止条件、交付条件或需要判断偏差时推进为“待复盘”；
4. 填写实际结果后由系统自动变成“已闭环”；
5. 未执行或不再执行时可以取消。取消是终态，不能再补写结果。

系统不允许从“已计划”直接写结果，也不允许手工把状态改成“已闭环”。结果有事实错误时可以修正，原写入与修正动作都会保留审计事件。

## CLI 示例

```text
praxis checkin-get --id <决策 ID>
praxis checkin-status --id <决策 ID> --status executing
praxis checkin-status --id <决策 ID> --status awaiting_review
praxis outcome --id <决策 ID> --file docs/examples/outcome-input.json
```

`checkin-status` 可用目标为 `executing`、`awaiting_review` 或 `cancelled`，是否允许取决于当前状态。CLI、Web 和原生客户端共用同一服务端门槛。
