# 本机运行时生命周期与跨客户端发现审计

状态：PARTIAL

日期：2026-07-30

## 范围与保护对象

本轮由外部 Windows 用户反馈的固定端口冲突触发，审查轻量版的端口分配、服务发现、启动失败诊断、单实例、状态文件、CLI/GUI API 认证和安全关闭。保护对象是 PGlite 事实数据、审计历史、运行时控制令牌以及其他本机应用的固定端口。

全量版的容器内端口、主机回环发布和反向代理入口继续保持显式固定配置；本轮不改变 PostgreSQL 拓扑、生产认证和跨设备同步边界。

## 已确认并修复

1. **固定端口冲突**：轻量本机默认不再绑定 `4310`，而是直接监听端口 `0`，由操作系统原子分配动态回环端口；不扫描低端候选端口。
2. **检查与使用竞态**：服务不执行“探测空闲端口后关闭再重开”，监听成功的 socket 就是正式 socket。
3. **跨客户端发现**：实际 URL 写入 `service.json`，Web 启动器、CLI、TUI、Windows GUI 和 Linux GUI 均读取同一状态。
4. **启动错误丢失**：后台标准输出和错误追加到用户数据目录的 `logs/service.log`；CLI 监视子进程，提前退出时报告退出码和日志路径，等待上限从 20 秒调整为 60 秒。
5. **数据库并发打开窗口**：服务在创建数据库前取得按运行目录划分的独占启动锁；迁移和种子命令在 PGlite 模式下也使用相同锁。正常关闭和启动失败均清理锁与状态。
6. **陈旧状态误判**：运行状态除 PID 存活外，还必须使用状态文件令牌成功读取受保护的 `/api/system/runtime` 实例确认端点，否则清理陈旧状态。
7. **访问模式契约漂移**：CLI 与 Windows/Linux GUI 统一携带运行时 API 令牌；服务允许该本机令牌访问版本化 API，而外部 Web 仍执行密码会话或可信身份头认证。
8. **显式端口边界**：设置 `APP_PORT` 时严格使用该固定端口；PostgreSQL 或非本机访问模式未设置固定端口时配置校验直接失败。

## 剩余风险和门槛

- 当前主机是 Windows，无法在本轮本机执行 GTK/AT-SPI 真实 GUI；Gitea Linux 作业通过后才能把跨平台结论从 PARTIAL 提升为 VERIFIED。
- 启动锁是用户目录中的原子文件加 PID 校验，不是操作系统持有式文件锁。崩溃后的死 PID 可自动恢复；极端 PID 复用会安全地拒绝启动，需要 `doctor` 辅助人工确认，不会冒险并发打开数据库。
- `service.log` 当前为追加文件，尚未实现大小轮换；日志内容不写控制令牌，但长期运行仍需后续增加有界轮换。
- 远程设备上的原生 GUI 尚未提供独立的远程服务配置流程；当前全量版跨设备共用入口仍是经过认证的 Web。这不影响本机轻量版验收，但属于后续客户端范围。
